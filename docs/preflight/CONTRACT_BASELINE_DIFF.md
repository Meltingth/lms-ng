# Contract baseline diff — v1 baseline (S2/S3) vs. candidate 2.0.0-draft.1

This compares the two legacy contract files shipped inside the revision pack against the
candidate contracts this round drafts. Every row is KEEP, CHANGE, or REMOVE, with the reason
and which test proves it. S2/S3 are read-only references (plan §A.0: "S2/S3 เป็น read-only
references ไม่ใช่แฟ้มให้ rewrite") — nothing in `reference/` is edited by this round.

**No PostgreSQL schema baseline exists to diff.** Searched the pack, WhizdomLift, and GitHub;
none found (`BASELINE_INVENTORY.md` §2). `0001_schema_v2_draft.sql` in this round has no v1
predecessor — it is drafted directly from Backend Plan §6 / revised plan §A.9 prose, not diffed
against prior SQL. Likewise no UI-enums baseline file exists; the enum list is drafted from
Backend Plan §5/§6/§13 and revised plan §A.11 directly.

## 2. Message envelope

| Field | v1 baseline | Candidate v2 | KEEP/CHANGE | Reason | Test |
|---|---|---|---|---|---|
| `schemaVersion` | `"1.0"` string | `"2.0"` string | CHANGE (version bump only, same mechanism) | — | C01 |
| `messageId` | UUID, required | UUID, required, **now explicitly "created once before durable enqueue; retry re-sends identical bytes"** | CHANGE (semantics tightened, not the field) | v1 declared `messageId` but never specified whether a retry could mint a new one. The revised plan's whole outbox/ACK design (§A.5) depends on `messageId` being immutable across retries — this is the field the backend's `ingest_receipt` dedupes on. | I02, I06 |
| `eventTime` | required, ISO string | **split into `eventTime` and `observedAt`**, both required, both explicitly "UTC RFC3339, the time the Gateway received the source record — never claimed as the exact instant the physical contact changed" | CHANGE | v1's single `eventTime` conflated "when the Gateway saw this" with an implied "when it happened," which the revised plan's honesty rules (§A.2, §D.3) forbid — the wire protocol (`ST <board_ms> <mask>`) genuinely cannot give a sub-second physical-event timestamp, only a receipt timestamp. | O02, U06 |
| `gatewayId` | present, no format constraint shown | UUID, format-constrained | CHANGE | Tightened for schema validation (C05). | C05 |
| `sequence` | plain integer (`sequence: 18442` in the example, a JS-safe number) | **`streamSeq`, decimal string**, plus new `streamId` (which stream this counts), `producerId`/`producerEpoch` (which registered installation/epoch owns the counter), `bootId` kept but demoted to "diagnostic only, not for ordering" | **CHANGE — this is the single largest breaking change** | v1's plain-integer, per-`bootId` sequence is exactly what revised-plan requirement R07 forbids ("คนละ boot เทียบ wall clock" / "ordering revisions และ counters ที่อาจเกิน JavaScript safe integer ส่งเป็น decimal string"). A restart under v1's scheme resets `bootId` and implicitly restarts the meaningful ordering context for consumers that (incorrectly, but plausibly) used `bootId+sequence` as if it were durable; the revised design makes the *durable* counter (`streamSeq` under a registered `producerEpoch`) syntactically and semantically distinct from the *diagnostic* one (`bootId`), and forces it to decimal-string encoding specifically because a `bigint` compared as JSON `number` silently loses precision past 2^53 in JavaScript — a real, not theoretical, failure mode for a counter that runs for months. | C04, O01, O03 |
| `payload` | free-form object | Same pattern (payload is `$ref`'d, not inlined) but validated with `unevaluatedProperties:false` at the **assembled root only**, not on every nested base schema | CHANGE (schema-composition mechanics) | Plan §A.11 / test C03: a naive `additionalProperties:false` on every layer of an `allOf` composition rejects perfectly valid extended payloads (a known JSON Schema footgun, [T2]); the revised approach opens base schemas and closes only the final assembled shape. | C03 |
| Origin / provenance | **absent** — no field distinguishes a live reading from a simulated or imported one | New required field `origin: LIVE \| SIMULATED \| IMPORT`, **immutable**, explicitly "offline retry ของ LIVE ยังคง LIVE" | **NEW (addition, not present in v1 at all)** | This is the mechanism that makes D03 ("Demo zero contamination") and S01 ("REAL/TEST topic ACL") provable instead of asserted. v1 had no way to express this at all — the topic-root split (item 1 above) and this field are the two halves of the same requirement. | D01, D03, S01 |
| Clock quality | absent | New field `clockQuality: SYNCED \| UNSYNCED \| UNCERTAIN` (+ optional offset/uncertainty) | **NEW** | Directly answers open item O2 concern about NTP not being verified yet; lets a consumer refuse to certify cross-machine latency (plan §D.5, test U08) rather than silently trusting an unsynced clock. | O02, U08 |
| `sourceRef` | absent | New field: capture session + offset/source-record-id + decoder/signal-config version | **NEW** | Needed for crash recovery (G07: "recover source cursor ไม่ทำ record ซ้ำหรือข้าม durable source") and for retrospective reprocessing when a floor-mapping version changes (plan §F.1). | G07, U10 |

## 8. Summary counts

- **KEEP:** 9 items (topic root pattern reused with v2 suffix, `direction` enum, `floorRaw` type, `floorDisplay` REST-side shape, `activeAlarmCount`, REST base path, `bearerAuth` scheme, heartbeat cadence/QoS, diagnostics topic role).
- **CHANGE:** 19 items, the two most consequential being (a) the envelope's sequence/identity scheme (`bootId`+int → `streamId`/`producerEpoch`/`streamSeq` decimal string) and (b) removing `floorDisplay` from the Edge's MQTT payload, which corrects a real contradiction between the v1 baseline contract and this project's own governing documents rather than being a stylistic choice.
- **REMOVE:** 2 items (`telemetry/.../signals/{signalCode}` point-level topic; Edge-reported `tripCount`).
- **NEW:** 7 items with no v1 precedent (`origin`, `clockQuality`, `sourceRef`, `motion`, `changes[]`, the full WS envelope, snapshot/delta reconciliation protocol).
- **DEFER:** 2 items (command request/result topics, config desired/reported topics) — explicitly reasoned, not silently dropped.

Every CHANGE/REMOVE/NEW row above is backed by a specific test ID from `TEST_MATRIX.md`; the
G-A decision packet cross-references this table so the owner can approve or reject line items,
not just the document as a whole.
